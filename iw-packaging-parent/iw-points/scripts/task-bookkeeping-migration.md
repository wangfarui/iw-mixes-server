任务自动记账 v1 迁移需在发布新版 `iw-core` 前完成。先备份数据库，再执行：

`iw-packaging-parent/iw-points/scripts/iw-points-migrate-20261010-task-bookkeeping.sql`

该脚本为一次性 MySQL 8 DDL，不重复运行；DDL 自动提交。新建环境使用更新后的 `iw-points-init.sql`，不再重复执行上述迁移。确认使用 InnoDB，以保证行锁与事务回滚。

历史计划 `bookkeeping_enabled=0`、模板为空；历史任务来源为空、当前完成奖励为零。不反推历史来源、不补建账单。历史任务的旧奖励无法可靠追溯，本版不回填“实际发放值”。任务记账模板不支持附件；普通记账和任务自身的附件功能保持原有行为。

`points_task_bookkeeping` 没有软删除或级联外键。删除任务、计划或账单时保留任务快照。取消完成不清除账单关联：只要账单仍存在，再次完成就复用原账单；账单已删除时显示待记账，下次从待办切换为完成时按当前快照重新生成账单，并同步替换最近账单 ID 与记账时间。已完成任务重复提交完成不会补建，需先取消完成再完成。原账单不可访问时不能当作已删除处理。来源唯一键不含 `deleted`，不能通过删除任务重新生成同一期。

上述行为调整不增加数据库列或表。已有已删除账单的关联会在查询和完成时按账单有效性处理，无需执行清理 SQL。创建、删除关联账单与任务完成统一先锁任务，再锁账单及余额，防止并发操作破坏一致性。

可在隔离 MySQL 中验证迁移与数据库约束（脚本仅创建及删除自己生成的临时数据库，不读取业务库；账号需具备建库权限）：

```sh
python3 iw-packaging-parent/iw-points/scripts/verify-task-bookkeeping-schema.py \
  --socket /path/to/isolated/mysql.sock --user root
```

需密码时通过 `--defaults-extra-file /path/to/protected-mysql.cnf` 传入凭据，不将密码写在命令行。脚本验证历史默认值、永久来源唯一键、任务/账单关联唯一性、JSON 约束、回滚及两连接并发生成约束。它验证数据库约束，不替代通过 Spring 代理的服务事务与权限集成验证。

回退应用前先关闭自动记账并保留新列和关联表；不要通过删表或清空账单关联回退，否则再次升级后不能保证历史防重。
