# Dev Hub K8s 默认 Token 验收

验证环境使用本地 `iw-external`、隔离的 MySQL 8.0 和 Redis。CODING 和本机 Agent 接口由回环地址上的模拟服务提供。所有凭据均为测试数据。

| 编号 | 验证项 | 结果 |
| --- | --- | --- |
| AC-01 | 两个测试账号通过会话接口绑定。无个人配置时，TEST、UAT、PRD 均返回默认来源。状态接口只返回脱敏值，环境取值接口要求有效会话并禁止缓存。 | 通过，真实 HTTP 与 MySQL |
| AC-02 | 账号 A 保存 TEST 个人值后优先使用个人值，账号 B 继续使用默认值。A 删除个人值后恢复默认，其他环境继续独立生效。 | 通过，真实 HTTP 与 MySQL |
| AC-03 | 已连接时复用匹配的凭据版本，凭据变化时重新建立会话，验证未保存的输入后清理临时会话。 | 通过，Web 自动化测试 |
| AC-04 | 打开设置页检查 Token 列在配置状态之前，测试默认连接，保存个人值并确认恢复默认。检查桌面和 390 像素宽度下的布局。 | 通过，Chromium 实际操作及截图检查 |
| AC-05 | 打开 K8s 服务页查询 Deployment，并通过浏览器调用发布面板使用的 K8s 查询逻辑。 | 通过，Chromium 与模拟 Agent |

后端 `K8sTokenServiceTest` 和 `ZhaogangControllerTest` 共 8 项通过。Web 类型检查、生产构建和 K8s 定向脚本通过。隔离数据库、测试服务和浏览器会话已清理。真实 CODING、K8s Dashboard 和生产配置未参与本次验证。
