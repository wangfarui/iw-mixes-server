# Dev Hub 提交行数比较补算验收

2026-11-27。以共享代码统计实现为基线，本次改动涉及 iw-external 和 Web。

| 场景 | 结果 | 证据 |
| --- | --- | --- |
| OpenAPI 契约 | 通过 | HTTP 夹具验证 `DescribeGitCommitInfo` 取得准确父 SHA，比较用当前 SHA 作为 `Source`，父 SHA 作为 `Target`。缺失计数字段被拒绝。 |
| 根提交、零值和权限 | 通过 | 后端用例覆盖根提交进入 Git、有变更但零行数保留未知、CODING 权限拒绝停止该凭证的比较和 Git 尝试。MySQL 用例覆盖另一有权凭证仍可补算。 |
| 自动补算 | 通过 | Git 禁用时自动任务补回超限记录。MySQL 验证可读仓库过滤先于批次上限，权限拒绝按凭证和读取方式记录，已无可用读取方式的记录不会重复入选。原 Git 权限挂起记录可进入比较路径。限流仍退避。 |
| 浏览器及接口联验 | 通过 | 在独立 Vite 页面点开「失败明细」，Git 权限文案留在抽屉内，个人令牌弹窗未出现。点击「补算失败行数」后，显示已处理 1/1、仍未统计 0 条。提交分页 0 次，diff、提交详情、比较接口各 1 次。 |
| 共享结果发布 | 通过 | 同一共享提交新增 6,197 行、删除 3,086 行、变更 98 个文件。个人和有权团队读到相同结果，权限收窄的团队不显示该提交。合成全员样本变更量更新为 9,403 行。数据库记录本轮暂缓文件类型补算，图表可使用未分类行数。 |
| 迁移与重跑 | 通过 | MySQL 8.0.46 验证新库初始化及共享统计升级。两条相同仓库与 SHA 的旧个人、团队记录合为一条并保留成功行数，连续执行两遍共享迁移及补算迁移，`missing_shared_commits` 均为 0。 |

后端 189 项相关测试通过，包含真实 MySQL。Web 权限提示回归、类型检查和生产构建通过。浏览器及接口联验使用本地 Java 后端和合成 CODING，Git 在该次运行中禁用。此次未验证真实 CODING 批量生产回填及自然定时窗口。隔离容器及数据卷已移除，后端、Vite、合成 CODING 进程已停止。
