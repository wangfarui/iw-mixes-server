# 2026-11-02 局部失败继续扫描与部分结果展示

用户要求：局部仓库失败不影响其余扫描，至少展示成功数据，并告警部分仓库失败。截图任务 5 的 INTERRUPTED 源于加载此前修复时的服务重启；其 5 个仓库局部读取失败并非造成整个任务中断的原因。

## 根因与修改

1. CodeStatsQueryService 原来在首次整月未完成时提前返回空统计。现根据实际已落库提交生成统计，RUNNING/PARTIAL/FAILED/INTERRUPTED 均可展示已有数据；保留完整任务状态，不将中断伪装成完成。扫描中绕过固定统计和明细快照缓存，展示实时部分结果。
2. CodeScanWorker 原来坏分支会 break 该仓库后续所有分支。现记录仓库失败但继续后续分支和其他仓库，保留已读取结果，最终 PARTIAL；仓库发现分页失败但已有部分仓库时也继续已有范围，coverageIncomplete 会进入 PARTIAL 判定。
3. 覆盖数据采用最新可用任务（必要时回退成功快照），失败明细与部分数据一并返回。待处理 PENDING diff 纳入行数覆盖率分母，避免未处理时伪报 100%。这补充了旧文档只计算已完成 diff 状态的口径。
4. 我的代码、团队代码的活动扫描约每 9 秒刷新已取得的统计；轮询防止重叠。扫描横幅在不完整时明确提示“当前展示已成功读取的部分数据”，有失败仓库时显示数量。
