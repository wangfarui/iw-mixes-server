# 记账支出人与家庭统计设计方案

更新日期：2026-10-14。按用户确认的展示、统计、钱包预算、权限与历史数据规则修订。后端与小程序代码已实现；目标数据库增量脚本待部署前执行。

## 1. 功能范围与含义

- 记账人：实际录入记录的人。
- 支出人：实际付款的人，不是消费受益人。自己付款给孩子买东西，支出人仍是自己。
- 代记账：替当前家庭中的其他成员录入该成员实际付款的支出；必须共享。
- 共享账单：允许同一家庭中有权限的成员查看的账单；共享不改变个人收支归属。
- 本期只新增支出人，收入沿用原用户归属，不增加代记收入。
- 一笔账只保存一条，不因记账人与支出人不同生成两条账单。

影响后端与原生微信小程序。Web 共用接口保证缺省字段兼容，本期不新增 Web 支出人选择界面。

## 2. 记账与展示交互

### 新建与编辑

- 有有效家庭组时，支出表单才展示“支出人”这一行；无家庭组时隐藏，新增默认本人。
- 每次新建、连续记账均默认本人，不沿用上次选中的家人。
- 可选择当前有效家庭成员；儿童只能为自己记账。
- 本人支出沿用现有共享默认值和开关规则。
- 选择其他成员后自动开启并锁定共享，提示“替家人记账，自动共享”；切回本人恢复本次选择家人之前的共享设置。
- 编辑回显原支出人；不能因为字段隐藏、旧客户端未传或当前没有家庭而重置历史支出人。
- 收入表单始终不展示“支出人”。

### 列表与详情

- 首页最近账单、账单页、明细、统计排行与年度账单列表：有家庭时，只有支出人不是当前查看者的支出才显示“支出人：某某”。
- 比较的是当前查看者与支出人，不是记账人与支出人。A 替 B 记账，A 看列表显示“支出人：B”，B 看同一条记录不显示支出人。
- 无家庭时不新增支出人展示行；离组后的历史代记保留实际支出人，必要的身份信息放入详情的历史记录说明。
- 有家庭时详情分别展示记账人和支出人，方便追溯；列表不重复显示“支出人：我”。
- 原“来自某某”类展示要明确表示记账人，不能混作支出人。

### 各入口

- 普通记账、快速记账、语音确认页使用同一规则。
- 快速记账的支出人选择放在“更多”弹层中，不占用主面板。
- 语音直接自动保存默认本人；代记须明确选择成员后确认，不根据语音里的姓名猜测用户账号。
- 导入默认原导入用户为支出人，不从备注推断。
- 任务自动记账默认任务原归属用户为支出人，并保留原任务账单约束，不开放更换支出人绕过任务规则。

## 3. 查询与统计：个人、家庭两种口径

共享表示家庭可见权限。统计只区分个人和家庭，不新增“仅共享账单”或“全部可见”第三种统计口径。

| 范围 | 支出纳入规则 | 收入纳入规则 |
| --- | --- | --- |
| 个人 | 支出人是当前用户的全部支出，含共享、不共享及家人代录 | 原收入归属为当前用户的全部收入，含共享与不共享 |
| 家庭 | 本人全部支出，加当前家庭中其他成员共享的支出 | 本人全部收入，加当前家庭中其他成员共享的收入 |

家庭统计按查看者可见范围汇总。自己的不共享账单仍计入自己的家庭统计，其他成员不共享的账单排除。因此各成员的家庭统计可能不同，差额由各自私人账单造成，符合已确认的规则。

### 查询规则

当前查看者为 U：

- 本人支出：`record_category = 支出 AND expense_user_id = U`。
- 本人收入：`record_category = 收入 AND user_id = U`。
- 个人范围：本人支出或本人收入。
- 家庭共享范围：属于 U 当前有效家庭且状态为共享中的账单。
- 家庭范围：个人范围与家庭共享范围的并集。

统一追加未删除、日期、分类、标签、金额及是否计入统计等筛选。按记录 ID 去重，本人共享账单同时满足两部分条件也只计一次。

- A 替 B 录入：计入 B 的个人统计，不计入 A 的个人统计；家庭范围计入一次。
- 筛选某位家庭成员只能缩小当前可见集合，不能查看该成员的私人账单。
- 无家庭时仅个人范围；儿童保留仅本人范围，不得通过请求参数突破。
- 沿用现有个人/家庭查询偏好，统一在“我的 → 家庭组”设置；记账记录、支出/收入统计及年度统计不增加独立范围选择入口。
- 切换范围同步刷新对应明细和统计。先加载家庭信息再生成参数；家庭查询失败时提示重试，不将不完整结果当作完整家庭统计。
- 记账人可追溯自己的历史代记记录，但该支出不因此进入其个人统计。历史追溯权限与金额统计归属分别判断。

### 全部统计统一

首页金额和最近账单、账单页、明细及顶部汇总、月度与年度支出/收入、分类、标签、排行、趋势、年度总览及下钻，统一使用范围、日期、成员和是否计入统计条件。

相同筛选下明细合计与统计总额一致；下钻必须保留原筛选。“不计入统计”继续沿用现有可选过滤行为，收入统计也需要一致处理。

年度金额与收支笔数按以上范围计算。“我的记账习惯”中的本人录入次数、连续记账天数按记账人计算并独立标注，不把家人代录说成本人录入。

## 4. 数据模型与接口兼容

保留现有 `user_id` 表示记账人，新增 `expense_user_id` 表示支出人；不直接把 `user_id` 改成家人 ID，以免改变编辑权限及通用数据语义。

| 字段 | 含义及规则 |
| --- | --- |
| `user_id` | 记账人，由登录态或可信业务上下文赋值，创建后不可修改 |
| `expense_user_id` | 实际支出人；支出须有值，收入不使用 |
| `group_id` | 原共享所属家庭，沿用 |
| `share_state` | 不共享、共享中、已离组，沿用 |

- 新增/更新 DTO 增加 `expenseUserId`；列表、详情、排行及年度相关 VO 返回记账人、支出人的 ID 和展示名。
- 新增未传支出人默认原业务归属用户，普通手工记账即当前登录用户；更新未传则保留原值，不能重置为登录用户。
- 收入不能借支出人字段改变归属。
- 历史回填完成前，读逻辑以原 `user_id` 兜底；回填后支出记录保证有支出人。
- 沿用 `/bookkeeping-service/bookkeeping/**` 入口和 `queryOnlyMyself` 两种范围。
- 为记账集中实现个人/家庭权限条件。不能在原 `user_id = 当前用户` 后简单追加支出人条件，否则会漏掉家人代录。
- 不全局改变其他业务的 `user_id` 权限语义。

## 5. 保存与维护权限

- 非儿童家庭成员允许为当前有效成员代记，儿童只能本人。
- 新增代记、更换支出人时，服务端校验双方同属有效家庭、目标成员有效，家庭 ID 从服务端取值。
- 支出人与记账人不同时强制共享；提交 `shared = 0` 也不能形成私人代记。
- 无家庭、目标退出、成员无效或家庭校验失败时拒绝新增代记/转交；不静默改为本人或私人账单。
- 记账人负责编辑、删除；支出人和其他有权查看的成员只读。群主、家长不自动获得修改他人账单的权限。
- `canEdit` 根据记账人与原业务约束计算，不按支出人直接授权；类型不可修改，任务账单保留原约束。

## 6. 钱包与预算

| 支出操作 | 钱包处理 |
| --- | --- |
| 新增 | 扣支出人的钱包，不扣记账人的钱包 |
| 修改金额 | 按新旧金额差额调整原支出人的钱包 |
| 删除 | 冲回原支出人的原金额 |
| 更换支出人 | 冲回原支出人的原金额，再扣新支出人的新金额 |
| 更改共享状态 | 不改变钱包余额 |

以保存前后真实记录计算变化，不能用登录用户代替支出人。记录与钱包变化须保持一致，避免重试、重复事件、并发编辑造成漏扣或多扣；钱包不存在等失败不能留下半完成账单。

收入钱包、收入激励和任务积分保留原归属，不因新增支出人额外给记账人加减积分。

预算仍是个人预算，实际消耗按支出人计算：家人替我记的计入我的预算，我替家人记的不消耗我的预算。分类、周期、是否计入预算等沿用现有规则；进度与相关定时结算同样调整。

切换家庭统计不使用家庭总额对比个人预算；预算页不增加额外的个人预算说明文案。

## 7. 历史迁移与离组

- 历史支出以原 `user_id` 回填支出人，不从备注猜测历史代记。
- 回填不重新扣钱包、不重算历史钱包流水、不改变共享状态；历史经济归属不变。
- 代记任一参与人离开原家庭后，停止向原家庭其他成员共享；记账人与支出人仍可追溯，支出人的个人统计和钱包归属保留。
- 保留原家庭 ID 与离组状态，不自动共享给新家庭，也不因重新加入自动恢复共享。
- 已离组代记锁定支出人，不能改成原家庭或新家庭另一成员；记账人仍可按原权限修改金额、备注或删除，钱包变化针对历史实际支出人。
- 无家庭时隐藏输入行不能抹掉历史支出人；详情历史说明保留身份。
- 离组处理覆盖记账人或支出人，不再仅依据原 `user_id`。
- 原家庭其他成员不能通过旧详情链接继续查看已终止共享的代记。

## 8. 当前统计差异的核查

当前代码中支出、收入和年度统计入口已接入共享查询，小程序也传递 `queryOnlyMyself`。现有查询总体符合“本人全部加家庭共享”方向。

“明细可见共享账单、统计似乎仅本人”的现象尚未实际复现。实施时核对线上版本、范围参数、角色、共享状态、日期/是否计入统计过滤，以及每条统计 SQL 的权限条件。

已发现明细会等待家庭信息加载，而支出、收入和年度统计页缺少相同步骤；这是待验证原因之一，不能直接认定为唯一原因。

## 10. 验收示例

同一月发生以下支出，均未删除且计入统计：

| 记账人 | 支出人 | 共享 | 金额 |
| --- | --- | --- | --- |
| A | A | 否 | 100 元 |
| A | A | 是 | 200 元 |
| B | B | 否 | 80 元 |
| B | B | 是 | 300 元 |
| A | B | 是，强制 | 50 元 |

| 查看者 | 个人支出 | 家庭支出 |
| --- | --- | --- |
| A | 300 元 | 650 元 |
| B | 430 元 | 630 元 |

A 家庭范围排除 B 私人 80 元；B 家庭范围排除 A 私人 100 元。家庭金额不同符合已确认的可见性规则。

- 50 元代记只扣 B 钱包、只消耗 B 个人预算；A 列表显示“支出人：B”，B 列表不显示。
- 代记只保存一条；家庭范围计入一次，A 个人不计入，B 个人计入。
- B 私人 80 元不能通过 A 的成员筛选、排行或详情链接泄露。
- 相同筛选下明细、月度与年度对应区间合计一致；收入也按相同个人/家庭范围规则验收。
- 覆盖共享开关、代记强制共享、切回本人、连续新建默认本人、编辑回显及旧客户端缺省。
- 覆盖修改金额、更换支出人、删除、重复请求/事件、钱包失败、并发编辑与任务约束。
- 覆盖无家庭、儿童、目标退出、家庭查询失败和离组后的历史权限。
