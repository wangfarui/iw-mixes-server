# 会员类型迁移运行说明

适用于已经安装 dictionary-v2 的 MySQL；本包不修改旧迁移脚本，不补齐现有用户的缺失4004来源。

1. 明确目标主机和库；执行 `00-preflight.sql`，留存字段/索引、4004模板、来源分布及异常映射清单。存在家庭4004、当前重名、非法名称或不兼容字段时停止，单独核对，不自动删除或套模板。
2. 完整备份订阅表、base_dict、结构并验证恢复；停止订阅写入、字典写入和自动续费，保持停写至全部复验结束。生产执行另获明确授权。
3. 用显式目标库运行 `SET @iw_mtype_migration_approved=1;` 后执行 `01-migrate.sql`，任何 SQL 错误都停止，不使用 `--force`。DDL有隐式提交，失败后保持停写，检查已完成的结构，不自动回滚二进制。
4. 执行 `02-verify.sql`，必须观察 `MEMBERSHIP_MIGRATION_PASS` 及完整/待核对数量。保存待核对清单；停用但唯一且未删除的来源可保留迁移时名称，缺失、删除、code=0、重用、多个候选不回填。数据库现值不能恢复旧入口曾覆盖的原始名称。
5. 同一停写窗口重跑01、02；第二次迁移数应为0，订阅及字典全部列哈希不变。新字段/索引的已有定义必须与交付相同；名称为32码点utf8mb4_bin，二进制唯一键保留大小写区别。
6. 先迁移结构再启动新版后端，再切换小程序/Web；旧4004通用入口全部拒绝，新版后端拒绝旧编码新增/变更，旧客户端仅可用未变化的原编码更新其它字段。自动续费无需选型并保留快照。验证兼容窗口后恢复写入。

恢复：用已验证备份在明确停写窗口恢复订阅、字典及结构，核对整个表和关联数据；已有新来源ID写入后，不能仅删字段或直接回退旧二进制。迁移基线保存原业务字段，不含认证数据；保留至发布观察及恢复窗口结束。02仅适用于本次停写队列，恢复业务写入后不再以旧基线判定当前业务数据。

默认初始化：新注册用户4004模板只初始化一次；已有历史（含停用/删除）不通过修复或重放补回。本脚本不批量向旧用户添加模板。
