### 数据归属与持续同步

- **工时**以 `codingTeamId + codingUserId` 归属本地记录和任务，按 CODING 工时登记 ID 去重。采集始终传目标成员的用户 ID。沿用个人 PAT 优先、仅未绑定时选择合格管理令牌的工时规则。保留每 15 分钟增量和既有回扫，沿用成功上界的重叠窗口及首次历史起点。日期筛选使用登记时间 StartAt，采集边界沿用现有提交时间口径。
- **代码**以 `codingTeamId + depotId + sha` 唯一保存 Git 提交及 diff 结果。按现有人工映射、邮箱哈希和唯一姓名规则归属成员。同一提交在各视图使用一致的作者归属，证据冲突则进入未归属处理。既有排除合并提交、跨分支去重、分支活跃度、文件类型和 diff 失败补算规则继续生效。
- **代码任务按仓库接续**。个人或团队入口负责发现和筛选当前可读仓库，仓库任务共用分支检查点。同一仓库重叠的手动与定时请求合并。沿用北京时间每 3 小时增量，先确认仓库可读并检查分支头，已有覆盖且分支未变时复用本地，新提交按增量获取。新仓库、检查点缺口或历史覆盖缺失只补对应范围，失败 diff 定向补算。
- **令牌切换**沿用现有已确认的数据和覆盖进度。新凭证无权读取的资源继续保存在本地，并从该视图的明细及各类汇总排除。个人授权与团队授权各自核验，某凭证完成的采集不自动授予另一身份读取权限。权限定界所需的目录或资源核验可异步完成。核验完成前，仅呈现仍有当前授权依据的部分。
- **同步后的发布**先发布数据、覆盖和进度，再使相关缓存失效并刷新受影响日期的本地报表。成员、角色、忽略设置和权限变化也更新相关报表。同步时间与报表生成时间分别显示，失败、排队和普通查库保持上次成功的同步时间。

## 4. 接口、版本与并发约束

- 公共接口前缀为 `/external-service/api/zhaogang`。优先兼容既有参数、返回结构和 Web 路由。工时 `GET /worklogs/report` 和 `GET /worklogs/entries/page` 查询，`GET /worklogs/sync` 读状态，`POST /worklogs/sync` 请求同步。代码继续使用 `GET /code-stats/statistics`、`/code-stats/member-statistics`、`/code-stats/entries`，以及 `GET /code-stats/scan` 查状态、`POST /code-stats/scan` 以 `mode=SYNC` 提交现有同步动作。全员继续使用 `GET /statistics/report`，`refresh=true` 合并请求本地报表任务。
- `SELF` 和 `WORKBENCH_TEAM` 继续表达查询与请求授权。后端从会话和团队成员关系解析身份。个人仓库范围按个人权限，团队仓库范围沿用当前合法统计凭证的可读范围。后台应按可验证的成员、项目或仓库确认覆盖来源并从本地读取权限结果。涉及工时事项快照时同样检查详情权限。
- 实施时将采集凭证、项目／仓库覆盖、数据版本和报告可见性分别建模。轮换时核验新凭证可用范围，并复用重合范围的进度。对于工时，单一成员级检查点可能不足以表达新增项目的历史缺口，应按实际查询能力保留覆盖信息。使用较窄权限得到的缺失结果只能修正已确认完整覆盖的范围。明确删除事实继续生效。
- 同一成员的工时写入及同一仓库的代码扫描使用稳定的任务键和现有数据库并发保护。重复请求合并。发布校验当前租约、数据范围及有效授权，阻止已失效凭证或迟到任务扩大当前可见性。失败批次保持安全的检查点，成功批次可持续发布。页面切换登录、团队、成员或日期后丢弃迟到响应。
- 缓存和快照按数据版本、作者归属版本、成员目录及可见性版本校验。权限收窄后旧快照、分页游标和缓存同样受限制。即使同步失败，当前仍授权且覆盖已确认的数据可以显示，并标注覆盖状态。旧报表在权限边界改变后需要重新过滤或重建。

在 `iw-external/scripts` 新增迁移脚本，并同步初始化结构。以下是接手实施时应落实的迁移顺序：

1. 核对数据库目标、版本、历史迁移和兼容性，记录旧数据的行数、去重键计数、有效 diff 数、覆盖区间和版本。先在隔离数据集验证，按实际切换方式决定是否需暂停旧写入。执行环境、备份和回退方式单独明确。
2. 保留旧表或可恢复快照，先建立共享结构。按稳定键迁移。工时保留可信的成员、登记 ID、历史及覆盖。代码合并相同仓库和 SHA，保留互相一致的成功 diff、文件类型和分支信息。冲突作者进入未归属。冲突 diff、无法证明连续的检查点和不完整旧覆盖按资源标记并定向修补，保留原证据供复核。
3. 断言跨组织归属正确、唯一键无重复、已确认的工时和代码历史有对应新记录、已确认的删除未复现、不可见的项目和仓库未进入查询。校验迁移前后的个人、团队和跨团队统计差异均能用去重、当前权限或证据冲突解释，并验证可重跑步骤幂等。
4. 断言通过后切换读写入口，并更新缓存与报告版本。断言失败时保留旧路径和原数据。接手会话需在运行说明中给出恢复顺序，并说明切换后若已有新写入，如何保全、补齐或回放，避免回退丢失数据。生产执行单独授权。
