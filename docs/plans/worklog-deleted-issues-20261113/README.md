# 工时首屏与已删除事项过滤设计

2026-11-13。方案已获用户确认并完成后端与 Web 实施。首屏按本地永久删除记录过滤，后台查验、删除版本缓存和页面自动更新已接通。本地隔离验收及限制见 [验收记录](ACCEPTANCE.md)，生产迁移和发布尚未执行。

## 依据与范围

用曾聪的同一个 PAT 实测，项目 `yuncunzheng` 的 `#8611` 在 `DescribeIssue` 返回 `InvalidParameterValue / issue_not_exist`。全项目工时接口仍返回内部事项 ID `34996761` 对应的两笔登记，分别为 2026-11-05 的 4 小时和 2026-11-06 的 7 小时。CODING 官方说明删除的事项无法恢复。[CODING 项目协同常见问题](https://coding.net/help/docs/collaboration/faq.html)

后端负责删除记录、异步查验和结果失效，Web 负责首屏及后台查验后的更新。涉及个人工时、团队工时、缺勤和工时记录。

## 删除记录

新增 MySQL 表 `external_zhaogang_worklog_deleted_issue`，主键为 `(coding_team_id, coding_issue_id)`。使用工时接口返回的正数 `IssueId` 定位事项。保存 `project_name`、`issue_code`、`first_confirmed_at` 供排查。该时间是工作台发现时间，删除实际发生时间由 CODING 决定。记录无 TTL，同一事项重复写入幂等，工时记录原样留在 CODING。

项目名和编号用于调用详情接口。以返回工时的同一成员 PAT 查验，且仅在请求明确得到 `InvalidParameterValue / issue_not_exist` 时将关联的内部事项 ID 记为已删除。权限错误、超时、限流及结构异常都保留工时。工时缺少可信内部 ID 时保留记录，不用项目内编号写入永久删除记录。接入前用相同工时样本核对详情的项目、编号和内部 ID 对应关系，并验证受限 PAT 的错误类型。若实测发现权限隐藏也会返回同一错误，需先取得有项目读取权限的凭证复核该候选，才能永久记入。

## 首屏与后台查验

1. 首屏按原有规则拉取工时，按北京时间 `StartAt` 归日。批量取本次工时涉及的内部事项 ID，与本地删除记录匹配。先过滤，再计算月报和缺勤并缓存。缺勤和月报使用同一份过滤后的工时数据，继续应用工作日历、请假、截止昨天和部分失败规则。工时明细使用同样的删除过滤。
2. 工时取数后提交后台查验，任务提交不占用工时响应的等待时间。用同一 CODING 团队、PAT 指纹及项目事项去重在途任务，命中永久删除记录直接跳过。沿用现有按 PAT 交错调度、有限并发及限流。正常查验结果短期复用，建议沿用当前 5 分钟作为下次查验资格；失败按类型退避，凭证变更后可重试。只处理本次已获取的工时关联事项，避免为此扫描全团队历史。排队饱和或服务重启时，尚未查验的候选由后续访问补查，界面如实结束当前等待状态。
3. 手动刷新重新拉工时，并提高当前范围后台查验的优先级。返回报表时只等待取数和本地过滤。明细滚动到可见区域后先展示工时登记和已有标题，后台补齐未命中的标题、类型与链接。明细的补齐和删除查验复用同一查验结果，按成员 PAT 隔离详情。
4. 首屏耗时主要取决于工时拉取。此前 7 人团队的分页实测约 1.6 秒，后台查验结束前，刚删除的事项仍可能短暂计入首屏。5 分钟指已查验事项的复用时长。新删除发现依赖后续访问和后台队列，受 CODING 接口可用性影响。

## 报表更新和缓存

在 MySQL 为每个 CODING 团队维护删除记录版本。新增永久删除记录和版本递增在同一事务完成，重复发现同一事项不递增。月报与缺勤的共用快照、日期范围明细都按团队删除版本隔离 Redis 缓存。读取缓存前取版本；生成快照时用读取删除记录所对应的版本写缓存，避免旧请求用新版本发布旧数据。正常沿用 60 秒报表 TTL。后台结果持久化后，旧版本缓存自然过期，下一次查询立即使用新的删除记录。

工时响应通过 `issueCheck` 附带 `deletionRevision` 和可选的后台查验状态引用。候选新增时，Web 对当前范围的状态做有界短轮询，状态读取只查本地，绑定原有会话与团队权限。发现版本变化时刷新当前月报，以及已打开的缺勤和已加载的明细；未发现删除时结束轮询。报表在查验期间继续可读。切换月份、团队、个人或离开页面后取消轮询，旧响应不能覆盖新范围。轮询结束后再次访问或刷新仍会读取最新版本。

## 实施与自验

| 顺序 | 项目与入口 | 改动 |
| --- | --- | --- |
| 1 | 后端 `iw-external` 初始化 SQL 和新增迁移脚本 | 新增删除记录与版本结构，先执行结构迁移再启动新版服务 |
| 2 | 后端 `worklog/WorklogQueryService`、`DefaultWorklogModule`、`WorklogViewCache` 和 `CodingIssueSnapshotLoader` | 接入本地批量过滤、后台查验、版本缓存键及状态查询 |
| 3 | Web `WorklogDashboard.vue`、`src/api/zhaogang.ts` 和 `src/types/zhaogang.ts` | 接入有界轮询、刷新和明细补齐 |

通过当前 `/external-service/api/zhaogang/worklogs/statistics`、`/absences` 和 `/entries` 验证业务行为，状态接口沿用同一前缀和权限边界。

| 编号 | 操作 | 预期 |
| --- | --- | --- |
| AC-01 | 后台详情接口模拟延迟，加载个人、团队月报和缺勤 | 首屏响应与详情延迟无关，HTTP 请求不等待 `DescribeIssue` |
| AC-02 | 用已存在的 8611 样本只读复核，或在本地隔离环境模拟两笔工时 | 首次查验确认后落一条删除记录，后续过滤两笔共 11 小时。月报、排行榜、缺勤、明细同步更新。服务重启后仍过滤 |
| AC-03 | 同一事项跨成员、跨日期范围重复发现，另一个项目含相同编号 | 永久记录只写一条。其他项目同号事项继续计入 |
| AC-04 | 模拟无权限、超时、限流和缺少内部 ID | 工时保留，永久删除表没有对应写入 |
| AC-05 | 并发生成快照时后台写入新删除记录，或前端快速切换范围 | 新版本不会命中旧统计，迟到响应不覆盖新页面 |
| AC-06 | 回归跨周补登、个人请假、当月缺勤和成员部分失败 | 与现有口径一致，删除工时在按日聚合之前被排除 |

建议用本地隔离环境验证迁移、并发和缓存，使用已存在的 CODING 样本做只读对照。实施时按两个业务仓库的 AGENTS.md 核对当前未提交改动，运行后端专项测试和 Web 类型检查、构建与本地浏览器自验。生产迁移及发布需另行授权。

后续接续时先读取 [验收记录](ACCEPTANCE.md)，核对两个仓库已有未提交改动。实施已完成；现有环境的结构迁移、版本整理、提交与发布需要按用户后续指令分别处理。
